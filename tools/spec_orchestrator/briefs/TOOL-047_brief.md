## Tool: `generate_sdk`

### Overview parameters
- Tool name: `fastapi_generate_sdk`
- Category: EVOLVE
- Complexity: Medium
- Dependencies: existing FastAPI project with OpenAPI schema, optional openapi-generator-cli
- Signature: `generate_sdk(project_dir: str, languages: list[str], output_dir: str = "sdks", package_name: str | None = None, publish: bool = False, registry: str | None = None) -> dict`
- Parameters:
  - `project_dir`: project root
  - `languages`: list of `python`, `typescript`, `go`, `rust`, `java`
  - `output_dir`: where generated SDKs are written
  - `package_name`: SDK package name (default: derived from app title)
  - `publish`: push to registry (PyPI, npm, etc.) after generation
  - `registry`: registry URL override

### Purpose
Generate typed client SDKs from the FastAPI OpenAPI schema for multiple languages. Uses openapi-generator-cli or openapi-python-client for Python, with fallbacks to native generators for each language. Each SDK includes: typed request/response models, retry/timeout/circuit-breaker helpers, authentication helpers (Bearer, API key, OAuth2), pagination iterators, and a typed exception hierarchy mapped from HTTP errors. CI workflow automates regeneration on every OpenAPI change. Versioning is tied to the API version (semver). Publishing is optional and off-by-default.

### Performance SLOs
- Tool execution time < 10s per language (excluding publish)
- Files modified ≤ 3 (pyproject.toml, CI workflow, Makefile)
- Files created ≥ 15 (generators per language, CI workflow, version manager, publish script, tests, docs, templates, Makefile targets)
- Schema extraction < 500 ms
- Generator invocation < 5s per language
- Publish step (if enabled) < 30s per language

### Key technical decisions
1. **OpenAPI as source:** schema extracted from the live FastAPI app at generation time
2. **Per-language generators:**
   - Python: `openapi-python-client` (httpx + attrs)
   - TypeScript: `openapi-typescript-codegen` or `orval`
   - Go: `oapi-codegen`
   - Rust: `openapi-generator-cli` with rust-reqwest
   - Java: `openapi-generator-cli` with java8
3. **Semver alignment:** SDK version = API version (major.minor.patch)
4. **Exception mapping:** 4xx/5xx mapped to typed exceptions (`NotFoundError`, `ValidationError`)
5. **Auth helpers:** Bearer, API key, OAuth2 client credentials flow
6. **Pagination iterators:** auto-detected cursor/offset pagination → `AsyncIterator`
7. **Retry/timeout:** exponential backoff with jitter, configurable per call
8. **Publish:** dry-run by default, requires `--publish` flag
9. **CI integration:** regenerate on OpenAPI change, commit to `sdks/` or separate repo
10. **Tests:** each SDK has smoke tests against the running API

### Key invariants
1. Schema is ALWAYS extracted live (never from stale file).
2. Version is ALWAYS aligned with API version (semver).
3. Publishing NEVER happens without explicit `--publish` flag.
4. Every SDK ALWAYS includes typed exceptions.
5. Auth helpers are ALWAYS generated if security schemes present.
6. Regeneration is IDEMPOTENT (same schema → same output, byte-identical).
7. CI job blocks PR if SDK out of sync with schema.

### Edge cases (15)
1. First generation (no existing SDK) → scaffold created
2. Schema unchanged → SDK regenerated byte-identical
3. Schema breaking change → major version bump suggested
4. Schema non-breaking → minor or patch
5. Publishing to PyPI with existing version → error (version collision)
6. Generator tool missing → install instruction printed
7. Network error during publish → retry with backoff
8. TypeScript SDK with ESM + CJS → dual package published
9. Go SDK with module path → honored via package_name
10. Java SDK with Maven vs Gradle → both build files generated
11. Tool re-run idempotent
12. OpenAPI uses `oneOf` unions → generated as union types
13. Required security scheme → auth helpers mandatory
14. CI job fails if `sdks/` drift → PR blocked
15. Large schema (500 routes) → generation still < 30s

### Anti-patterns
- DO NOT commit unpublished SDKs to the same repo as monolith (separate repo preferred)
- DO NOT skip typed exceptions (consumers lose visibility)
- DO NOT publish on every commit (use explicit release)
- DO NOT version SDKs independently of API (causes drift)
- DO NOT generate from cached schema (always live)
