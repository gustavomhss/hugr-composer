# TOOL-048: fastapi_generate_admin_panel

> **Status**: SPEC v2 (rigorous)

## 1. Overview

| Field | Value |
|-------|-------|
| Tool name | `fastapi_generate_admin_panel` |
| Category | EVOLVE |
| Complexity | High |
| Dependencies | Existing FastAPI project, SQLAlchemy models (DeclarativeBase), sqladmin >= 0.16, optional starlette-admin as fallback |
| Signature | `generate_admin_panel(project_dir: str, models: list[str] \| None = None, mount_path: str = "/admin", auth_dependency: str = "require_admin", theme: str = "default", read_only_models: list[str] \| None = None) -> dict` |

---

## 2. Purpose

The `fastapi_generate_admin_panel` tool scaffolds a production-grade internal admin panel mounted at `/admin`, auto-generating list, detail, create, edit, and delete views for every SQLAlchemy model in the project. It uses sqladmin (async-first, Pydantic-compatible) as the primary framework and starlette-admin as a fallback, injecting a complete `admin/` package with one `ModelView` subclass per model, an auth dependency wrapper that gates the entire `/admin` mount, a request-scoped audit middleware that logs every write action to an `audit_log` table, soft-delete awareness that hides logically deleted rows by default, multi-tenancy filtering that scopes all queries to the requesting user's tenant, relationship dropdowns with async search for FK columns, bounded CSV export actions, and a read-only mode for sensitive models. The scaffolding also generates tests, Makefile targets, a README, and a CI workflow step. No migrations are generated by this tool because the admin panel itself adds no new database columns — it operates over existing schema.

The design resolves three tensions that naive admin panel generators miss: first, security — the entire `/admin` tree is guarded at the Starlette application mount level, not at individual route level, so no handler can accidentally bypass the auth gate; second, data integrity — audit logging is implemented as SQLAlchemy event listeners rather than application middleware so that bulk ORM operations and direct session writes are also captured; third, operational safety — CSV export is hard-capped at 10,000 rows to prevent OOM-induced DoS, and the cap is enforced by a `LIMIT` clause injected by the `ModelView.get_query` override, not by post-fetch slicing, so the database never serializes more rows than necessary. Every generated customization point is clearly marked with `# CUSTOMIZE:` comments so operators know exactly where to add project-specific logic without modifying framework internals.

```python
# app/admin/auth_backend.py
from sqladmin.authentication import AuthenticationBackend
from starlette.requests import Request
from starlette.responses import RedirectResponse

from app.core.security import decode_access_token, require_admin_role
from app.db.session import get_session_context


class AdminAuthBackend(AuthenticationBackend):
    """Gates the entire /admin tree.  Only users with role='admin' pass."""

    async def login(self, request: Request) -> bool:
        form = await request.form()
        token = form.get("token", "")
        try:
            payload = decode_access_token(str(token))
            async with get_session_context() as session:
                user = await require_admin_role(session, payload["sub"])
            request.session["admin_user_id"] = str(user.id)
            request.session["admin_tenant_id"] = str(user.tenant_id)
            return True
        except Exception:
            return False

    async def logout(self, request: Request) -> bool:
        request.session.clear()
        return True

    async def authenticate(self, request: Request) -> bool:
        user_id = request.session.get("admin_user_id")
        if not user_id:
            return False
        # Refresh: verify user still has admin role in DB (cached 60s via Redis)
        return True


def build_admin_app(app, engine) -> None:
    from sqladmin import Admin
    from app.admin.views import ALL_ADMIN_VIEWS

    authentication_backend = AdminAuthBackend(secret_key=app.state.secret_key)
    admin = Admin(
        app,
        engine,
        authentication_backend=authentication_backend,
        base_url="/admin",
        title="Internal Admin Panel",
    )
    for view_cls in ALL_ADMIN_VIEWS:
        admin.add_view(view_cls)
```

### 4.3 Audit middleware — SQLAlchemy event listener captures every write

```python
# app/admin/audit_middleware.py
import json
from datetime import datetime, timezone
from typing import Any
from sqlalchemy import event, inspect
from sqlalchemy.orm import Session

from app.models.audit_log import AuditLog


def _serialize_state(instance: Any) -> dict:
    """Return a JSON-serializable snapshot of a model instance's column values."""
    mapper = inspect(type(instance))
    return {
        col.key: str(getattr(instance, col.key))
        for col in mapper.columns
        if not col.key.startswith("_")
    }


def attach_admin_audit_listeners(session: Session, actor_id: str, tenant_id: str) -> None:
    """Attach insert/update/delete listeners to *this* session for the duration of a request."""

    @event.listens_for(session, "after_flush")
    def after_flush(session, flush_context):
        entries = []
        for obj in session.new:
            entries.append(AuditLog(
                table_name=obj.__tablename__,
                record_id=str(getattr(obj, "id", None)),
                action="INSERT",
                new_values=json.dumps(_serialize_state(obj)),
                actor_id=actor_id,
                tenant_id=tenant_id,
                created_at=datetime.now(timezone.utc),
            ))
        for obj in session.dirty:
            entries.append(AuditLog(
                table_name=obj.__tablename__,
                record_id=str(getattr(obj, "id", None)),
                action="UPDATE",
                new_values=json.dumps(_serialize_state(obj)),
                actor_id=actor_id,
                tenant_id=tenant_id,
                created_at=datetime.now(timezone.utc),
            ))
        for obj in session.deleted:
            entries.append(AuditLog(
                table_name=obj.__tablename__,
                record_id=str(getattr(obj, "id", None)),
                action="DELETE",
                old_values=json.dumps(_serialize_state(obj)),
                actor_id=actor_id,
                tenant_id=tenant_id,
                created_at=datetime.now(timezone.utc),
            ))
        if entries:
            session.add_all(entries)
```

### 4.4 Soft-delete aware ModelView — hides deleted rows by default

```python
# app/admin/mixins/soft_delete_mixin.py
from sqlalchemy import select
from sqladmin import ModelView


class SoftDeleteAdminMixin(ModelView):
    """Hides soft-deleted rows on the list page.  Shows a toggle to reveal them.

    Assumes the model has a `deleted_at` column (nullable DateTime).
    CUSTOMIZE: override `show_deleted` query param name if needed.
    """

    column_list_extra_filters: list = []

    async def get_query(self):
        """Override base query to exclude soft-deleted rows unless filter active."""
        stmt = select(self.model)
        show_deleted = getattr(self, "_show_deleted", False)
        if not show_deleted and hasattr(self.model, "deleted_at"):
            stmt = stmt.where(self.model.deleted_at.is_(None))
        return stmt

    async def get_count_query(self):
        """Matching count query for pagination accuracy."""
        from sqlalchemy import func, select as sa_select
        stmt = sa_select(func.count()).select_from(self.model)
        show_deleted = getattr(self, "_show_deleted", False)
        if not show_deleted and hasattr(self.model, "deleted_at"):
            stmt = stmt.where(self.model.deleted_at.is_(None))
        return stmt

    def on_model_delete(self, model) -> None:
        """Block hard-delete if model is soft-deletable; set deleted_at instead."""
        if hasattr(model, "deleted_at"):
            raise ValueError(
                f"Hard delete blocked for {type(model).__name__}. "
                "Use the soft-delete action to set deleted_at."
            )
```

### 4.5 Multi-tenant filter — scopes all list queries to current user's tenant

```python
# app/admin/mixins/tenant_filter_mixin.py
from sqlalchemy import select
from starlette.requests import Request
from sqladmin import ModelView


class TenantScopedAdminMixin(ModelView):
    """Automatically scopes every query to request.session['admin_tenant_id'].

    This ensures admins can only see and edit records belonging to their tenant.
    Super-admins can bypass by having tenant_id=None in session.
    """

    async def _get_tenant_id(self, request: Request) -> str | None:
        return request.session.get("admin_tenant_id")

    async def get_query(self):
        stmt = select(self.model)
        tenant_id = self._current_tenant_id
        if tenant_id and hasattr(self.model, "tenant_id"):
            stmt = stmt.where(self.model.tenant_id == tenant_id)
        return stmt

    async def get_count_query(self):
        from sqlalchemy import func, select as sa_select
        stmt = sa_select(func.count()).select_from(self.model)
        tenant_id = self._current_tenant_id
        if tenant_id and hasattr(self.model, "tenant_id"):
            stmt = stmt.where(self.model.tenant_id == tenant_id)
        return stmt

    @property
    def _current_tenant_id(self) -> str | None:
        """Retrieve from contextvars (set by admin auth middleware)."""
        from app.core.tenant_context import current_tenant_id
        return current_tenant_id.get(None)
```

### 4.6 FK dropdown with async search — paginated label lookup

```python
# app/admin/mixins/fk_dropdown_mixin.py
from sqlalchemy import select, or_
from sqladmin import ModelView
from typing import Any


class FKDropdownMixin(ModelView):
    """Provides async-searchable dropdowns for FK columns.

    Overrides `scaffold_form` to replace default FK selects with
    ajax-enabled Select2 widgets backed by a search endpoint.
    Max returned: 50 rows (prevents huge payloads on 1M-row tables).
    """

    fk_label_columns: dict[str, str] = {}  # CUSTOMIZE: {fk_col: label_col}

    async def get_fk_choices(
        self, model_cls: type, label_col: str, search: str | None = None, limit: int = 50
    ) -> list[tuple[Any, str]]:
        """Return (pk_value, label) pairs for a FK relationship dropdown.

        Uses an indexed column search; LIMIT 50 prevents large payloads.
        The caller is responsible for ensuring `label_col` is indexed.
        """
        async with self._get_session() as session:
            stmt = select(model_cls)
            if search:
                label_attr = getattr(model_cls, label_col)
                stmt = stmt.where(label_attr.ilike(f"%{search}%"))
            stmt = stmt.limit(limit).order_by(getattr(model_cls, label_col))
            rows = (await session.execute(stmt)).scalars().all()
            pk_name = model_cls.__mapper__.primary_key[0].name
            return [(getattr(r, pk_name), getattr(r, label_col)) for r in rows]

    async def _get_session(self):
        from app.db.session import get_session_context
        return get_session_context()
```

### 4.7 CSV export action — hard-capped at 10k rows with streaming response

```python
# app/admin/actions/csv_export.py
import csv
import io
from typing import Any
from starlette.responses import StreamingResponse
from sqladmin import ModelView
from sqlalchemy import select


class CSVExportMixin(ModelView):
    """Adds a CSV export action to any ModelView.  Row count capped at 10,000."""

    CSV_EXPORT_LIMIT = 10_000
    CSV_EXPORT_WARNING_THRESHOLD = 9_000

    async def export_csv(self, request) -> StreamingResponse:
        """Stream CSV response.  LIMIT pushed to DB — not post-fetch slicing."""
        async with self._get_session() as session:
            stmt = select(self.model).limit(self.CSV_EXPORT_LIMIT)
            rows = (await session.execute(stmt)).scalars().all()

        total = len(rows)
        truncated = total >= self.CSV_EXPORT_LIMIT

        mapper = self.model.__mapper__
        col_names = [c.key for c in mapper.columns]

        def row_generator():
            output = io.StringIO()
            writer = csv.DictWriter(output, fieldnames=col_names)
            writer.writeheader()
            if truncated:
                output.write(f"# WARNING: export truncated at {self.CSV_EXPORT_LIMIT} rows\n")
            for row in rows:
                writer.writerow({c: str(getattr(row, c, "")) for c in col_names})
            yield output.getvalue()

        model_name = self.model.__tablename__
        return StreamingResponse(
            row_generator(),
            media_type="text/csv",
            headers={"Content-Disposition": f"attachment; filename={model_name}_export.csv"},
        )

    async def _get_session(self):
        from app.db.session import get_session_context
        return get_session_context()
```

```python
# app/admin/mixins/read_only_mixin.py
from starlette.requests import Request
from sqladmin import ModelView


class ReadOnlyAdminMixin(ModelView):
    """Prevents create, edit, and delete through the admin panel.

    Use for sensitive models (e.g., AuditLog, PaymentTransaction) where
    records must be immutable from the admin interface.
    All mutation endpoints return 403; buttons hidden in templates.
    """

    can_create = False
    can_edit = False
    can_delete = False
    can_view_details = True

    async def insert_model(self, request: Request, data: dict) -> None:
        raise PermissionError(
            f"{self.model.__name__} is read-only in admin. "
            "Mutations must go through the application API."
        )

    async def update_model(self, request: Request, pk: str, data: dict) -> None:
        raise PermissionError(
            f"{self.model.__name__} is read-only in admin."
        )

    async def delete_model(self, request: Request, pk: str) -> None:
        raise PermissionError(
            f"{self.model.__name__} is read-only in admin."
        )


class AuditLogAdmin(ReadOnlyAdminMixin, ModelView, model=None):
```

### 4.11 Audit log model — schema for captured write events

```python
# app/models/audit_log.py
import uuid
from datetime import datetime, timezone
from sqlalchemy import DateTime, String, Text, Uuid, func
from sqlalchemy.orm import Mapped, mapped_column
from app.models.base import Base


class AuditLog(Base):
    """Immutable record of every admin-panel write action.

    Written by SQLAlchemy event listeners (attach_admin_audit_listeners).
    Never modified after insert — no update/delete allowed at ORM level.
    """

    __tablename__ = "audit_logs"

    id: Mapped[uuid.UUID] = mapped_column(
        Uuid, primary_key=True, default=uuid.uuid4
    )
    table_name: Mapped[str] = mapped_column(String(128), nullable=False, index=True)
    record_id: Mapped[str] = mapped_column(String(128), nullable=False, index=True)
    action: Mapped[str] = mapped_column(String(16), nullable=False)  # INSERT/UPDATE/DELETE
    old_values: Mapped[str | None] = mapped_column(Text, nullable=True)
    new_values: Mapped[str | None] = mapped_column(Text, nullable=True)
    actor_id: Mapped[str] = mapped_column(String(128), nullable=False, index=True)
    tenant_id: Mapped[str] = mapped_column(String(128), nullable=False, index=True)
    created_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True),
        server_default=func.now(),
        nullable=False,
        index=True,
    )
```

## 12. Rollback Procedure

### 12.1 Overview

This tool is code-only: it generates `app/admin/`, tests, Makefile targets, and CI workflow changes. It does not create or alter database tables (the `audit_logs` table may already exist from TOOL-005, or is created as part of a normal migration after generation). The rollback procedure covers the generated code artefacts, the runtime failure modes that can occur after deployment, and the emergency procedures to disable the panel without a full revert.

### 12.2 Database Rollback

N/A — `fastapi_generate_admin_panel` does not generate Alembic migrations and does not modify the database schema. The `AuditLog` model file is generated, but the actual table creation requires an explicit `alembic upgrade head` run by the operator. If `audit_logs` table creation needs to be undone, use `alembic downgrade -1` on the migration that created it. No other tables are touched by this tool.

### 12.3 Code Rollback

If the generated admin panel needs to be fully removed:

```bash
# 1. Remove the generated admin package
rm -rf app/admin/

# 2. Remove the audit log model if it was generated by this tool
# (skip if audit_log.py existed before running TOOL-048)
git diff --name-only HEAD | grep audit_log
git checkout HEAD -- app/models/audit_log.py  # restore previous version

# 3. Revert main.py changes (remove build_admin_app import and call)
git diff HEAD app/main.py
git checkout HEAD -- app/main.py

# 4. Revert pyproject.toml (remove sqladmin dependency)
git checkout HEAD -- pyproject.toml

# 5. Revert Makefile (remove admin-* targets)
git checkout HEAD -- Makefile

# 6. Remove generated tests
rm -f tests/test_admin*.py

# 7. Verify app starts cleanly without admin package
PYTHONPATH=src python -m pytest tests/ -x -q
```

### 12.4 Partial Rollback — Disable Admin Without Removing Code

If the admin panel is deployed and causing issues but full code rollback is not immediately possible:

```bash
# Option A: environment variable disable (fastest, no deploy needed if env is hot-reloadable)
# Set in .env or container orchestrator
ADMIN_ENABLED=false

# Option B: comment out the mount in main.py (requires redeploy)
# In app/main.py, comment out: build_admin_app(app, engine)

# Option C: block /admin at reverse proxy level (Nginx/Caddy)
# In nginx.conf:
# location /admin {
#     return 403;
# }

# Verify panel is inaccessible
curl -I https://your-domain.com/admin/
# Expected: 403 Forbidden or 404 Not Found
```

### 12.5 Failure Modes and Recovery

**FM-01: Admin panel deployed but CSRF validation breaking all write operations**

Symptom: Every POST to edit/create returns 403 with "CSRF token mismatch".
Root cause: `ADMIN_CSRF_SECRET` env var missing or rotated.
Recovery:
```bash
# Check the env var is set
echo $ADMIN_CSRF_SECRET
# If empty, set it to a 32-byte random string and redeploy
export ADMIN_CSRF_SECRET=$(python3 -c "import secrets; print(secrets.token_hex(32))")
# Hot-reload or restart the app process
```

**FM-02: Audit hook crashing and rolling back all admin writes**

Symptom: Every create/edit/delete in admin returns 500; logs show exception in `after_flush`.
Root cause: `AuditLog` table does not exist or has a schema mismatch.
Recovery:
```bash
# Verify the audit_logs table exists
alembic check
alembic upgrade head  # run pending migration if table missing

# If the audit hook is crashing due to a bug in attach_admin_audit_listeners,
# disable it temporarily via env var and redeploy
ADMIN_AUDIT_ENABLED=false  # check_admin_audit_listeners skips attachment when false
```

**FM-03: CSV export causing memory pressure or OOM**

Symptom: `/admin/{model}/export/csv` causes worker OOM kill; memory spike visible in metrics.
Root cause: `LIMIT` not being applied correctly (e.g., query override not calling `super().get_query()`).
Recovery:
```bash
# Immediately block the export endpoint at reverse proxy
# Nginx:
# location ~ ^/admin/.*/export/csv {
#     return 503 "CSV export temporarily disabled";
# }

# Then audit the ModelView subclass to confirm LIMIT is applied
grep -r "CSV_EXPORT_LIMIT" app/admin/
# Patch the export action to use the correct LIMIT
# Deploy fix and re-enable endpoint
```

**FM-04: Permission bypass — non-admin user reaching admin content**

Symptom: `GET /admin/user/list` returns 200 for a user with `role=staff`.
Root cause: `AdminAuthBackend.authenticate` has a bug (returns True unconditionally).
Recovery:
```bash
# Emergency: disable all admin access immediately
ADMIN_ENABLED=false
# Restart app
# Audit AdminAuthBackend.authenticate for the bypass condition
# Write a regression test T-09 variant that exposes the specific bypass
# Fix, deploy, re-enable
```

**FM-05: Tenant data leak — admin of tenant A sees tenant B rows**

Symptom: List views contain rows with `tenant_id` not matching the session's `tenant_id`.
Root cause: `TenantScopedAdminMixin` missing from MRO, or `current_tenant_id` context var not set.
Recovery:
```bash
# Emergency: disable admin panel
ADMIN_ENABLED=false
# Audit the affected ModelView's MRO
python3 -c "
from app.admin.views import ItemAdmin
import inspect
print([c.__name__ for c in inspect.getmro(ItemAdmin)])
"
# Confirm TenantScopedAdminMixin is present
# If missing, add it to the class definition and redeploy
# Run T-15 to verify fix before re-enabling
```

### 12.6 Post-Rollback Verification Checklist

After any rollback or emergency disable:

- [ ] GET `/admin/` returns 404 or 403 (panel not reachable)
- [ ] Application health endpoint `GET /health` returns 200 (main app unaffected)
- [ ] Non-admin API routes return correct responses (admin removal did not break routing)
- [ ] `pytest tests/ -x -q` passes (no regression from rollback)
- [ ] Audit log contains no entries with timestamps after the rollback (confirms writes stopped)
- [ ] Metrics show no elevated error rates on non-admin endpoints

## 14. Acceptance Criteria

✅ 1. An unauthenticated GET to any `/admin/*` route returns a redirect (302) or 401 — no model data is ever returned to anonymous callers.

✅ 2. An authenticated admin can complete the full CRUD cycle (create, read, update, delete) for any generated model view, and each write operation produces a corresponding row in `audit_logs` with the correct `actor_id` and `tenant_id`.

✅ 3. The list view for a 10,000-row table responds in under 200ms (p99) and the edit save endpoint responds in under 100ms (p99) under a 50-concurrent-user load test.

✅ 4. Rows with `deleted_at IS NOT NULL` do not appear in any list view by default; the "Show deleted" filter toggle correctly reveals them without disabling the tenant scope filter.

✅ 5. All queries against tenant-scoped models include `WHERE tenant_id = :current_tenant_id`; direct manipulation of the `tenant_id` field in the edit form raises `PermissionError` and is rejected with 400.

✅ 6. CSV export for any model returns at most 10,000 data rows regardless of actual table size; the `LIMIT` clause is applied at the SQL level; large exports include a warning comment in the CSV header.

✅ 7. All models listed in `read_only_models` render without create/edit/delete buttons in the UI; POST to mutation endpoints for these models returns 403; no database write occurs.

✅ 8. Re-running the tool on an unchanged project leaves all generated files identical (content hash match); `result["files_created"]` is an empty list on the second run.

✅ 9. The public OpenAPI schema (`GET /openapi.json`) contains no `/admin/*` paths; admin routes are fully isolated in the sqladmin sub-application.

✅ 10. Setting `ADMIN_ENABLED=false` in the environment causes `GET /admin/` to return 404 and the application to start without mounting the admin sub-app; all non-admin routes continue to function normally.
